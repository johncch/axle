# Migrating to Axle 0.29.0

0.29.0 renames the execution-loop unit from "turn" to **step**. One pass of
the tool loop — one provider request, the assistant message it yields, and
the tool batch that message requests — is a *step*. "Turn" now refers only
to the render-layer conversation entry (`History.turns`, `TurnEvent`), the
sense it always had there. See [terminology.md](./terminology.md) for the
full vocabulary.

This is a rename-only release: no behavior changes.

---

## Breaking changes

### `StreamEvent`

- `turn:start` → `step:start`
- `turn:complete` → `step:complete`

The former names collided with `TurnEvent`'s render-layer `turn:start` /
`turn:end`, which are unchanged. Consumers switching on `StreamEvent.type`
update the two case labels.

### Loop options and results

- `maxIterations` → `maxSteps` on `stream()` / `generate()` options (no
  alias; the old name is a type error).
- The `stopped` result marker `"max-iterations"` → `"max-steps"`.

### Renamed exports

- `generateTurn` → `generateStep` (single non-streaming model request).

### Observability

- Loop spans are named `step-N` instead of `turn-N`. Log pipelines or
  dashboards matching `turn-` span names update their patterns; span
  `type: "llm"` is unchanged.

## Unchanged

- `TurnEvent`, `Turn`, `History.turns`, `TurnAccumulator`, and everything
  else in the render layer.
- All wire-layer message types.
