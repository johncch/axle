# Migrating to Axle 0.34.1

0.34.1 turns on prompt caching for Anthropic and OpenRouter requests. No
signature changes; `AxleModelRequestOptions` gains an optional `cache`
flag. The change is to what every request sends, and therefore to what it
bills.

The Axle CLI is a separate product; its changes are recorded in
[packages/axle-cli/CHANGELOG.md](../packages/axle-cli/CHANGELOG.md).

---

## Anthropic and OpenRouter requests carry `cache_control`

Every request from `Agent`, `generate()`, and `stream()` to the Anthropic
provider, and every chat-completions request to the OpenRouter vendor, now
carries a top-level `cache_control: { type: "ephemeral" }`. Before 0.34.1
nothing did, so no Anthropic request through Axle was ever served from
cache.

What changes on your bill:

| Workload                                                 | Before                                             | 0.34.1                                                                          |
| -------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------- |
| An `Agent` tool loop, or any repeated prefix             | Every step re-bills the whole conversation at 1.0x | Each step reads the earlier steps at 0.1x and writes only the new tail at 1.25x |
| A one-shot prompt that is never repeated                 | 1.0x                                               | 1.25x on the cacheable part: a write with no read                               |
| A prompt under the model's minimum (512 to 4,096 tokens) | 1.0x                                               | Unchanged; the provider ignores the field silently                              |

`usage.cachedIn` and `usage.cacheWriteIn` already existed and now carry
non-zero values on these providers.

### Opting out

```ts
await generate({ provider, model, messages, cache: false });
new Agent({ provider, model, cache: false });
```

`cache: false` omits the field. It means "do not ask", not "do not cache":
OpenAI, Gemini and Together cache automatically and are unaffected by either
value.
An explicit `providerOptions.cache_control` still wins over the default, so
a host that already placed its own top-level marker, or wants the one-hour
TTL, is unchanged.

### OpenRouter needs a session for a hit

OpenRouter forwards the field to the upstream Claude host, and a hit needs
the next request to reach the same host. OpenRouter pins the host by
`session_id`. `Agent` always sends its `sessionId`, and from 0.34.1 a
`stream()` or `generate()` call without one generates an id and sends it on
every step of its own tool loop, so step 2 onward read what step 1 wrote.
Two separate calls still get two ids; pass the same `sessionId` to both to
get reads across them.
