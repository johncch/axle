# Migrating to Axle 0.36.2

The Axle CLI is a separate product; its changes are recorded in
[packages/axle-cli/CHANGELOG.md](../packages/axle-cli/CHANGELOG.md).

---

## Behavior changes

### A tool batch that ends early answers every call

When a turn was cancelled while a tool was running, when a tool threw
`AxleToolFatalError`, or when a turn ran out of `turnTimeoutMs` during a
tool call, the conversation kept the assistant message that requested the
calls and got no tool results message. The next request sent those calls
unanswered, and providers rejected it: after one such turn, every later
send on that agent failed.

The tool results message is now written before the error is thrown, with
one result per call in request order:

| The call                               | Its result                                              |
| -------------------------------------- | ------------------------------------------------------- |
| Returned before the batch ended        | Its real result                                         |
| Threw `AxleToolFatalError`             | `isError`, `{"error":{"type":"fatal","message":…}}`     |
| Was cut short by the cancel or a fatal | `isError`, `{"error":{"type":"cancelled","message":…}}` |

The send rejects as before, with the same error, and no further request is
made. What changes is what the rejection leaves behind:

```ts
// Before
agent.messages.map((m) => m.role); // ["user", "assistant"]
error.messages?.map((m) => m.role); // ["assistant"]

// 0.36.2
agent.messages.map((m) => m.role); // ["user", "assistant", "tool"]
error.messages?.map((m) => m.role); // ["assistant", "tool"]
```

This applies to `AxleAbortError`, `AxleAgentAbortError` and
`AxleToolFatalError`, from `stream()`, `generate()` and `agent.send()`.
Code that assumed the last message after a cancelled turn is the assistant's
now finds the tool results message there.

A session saved by an earlier version that already ends in unanswered tool
calls is not repaired. Remove the trailing assistant message, or append a
tool results message for its calls, before sending on it again.

The reasons are in
[architecture/tool-loop.md](./architecture/tool-loop.md), invariant 4.
