# Migrating to Axle 0.30.0

0.30.0 removes turns from the Agent. An Agent is a _continuation_: it carries
`sessionId` and the active model-facing `messages`, and nothing else. The
transcript — the append-only fold of the event stream — is owned by whoever
consumes the events: attach the shipped in-memory `Transcript`, persist its
`state` yourself, and re-seed it on restore. Lose that state, lose the
transcript; the Agent cannot recreate it.

Compaction is reworked into three layers, each with one job: `triggers` say
_when to ask automatically_, `shouldCompactOnTrigger` filters those automatic
requests, and `compact` does _the work_ — as ordinary fallible turn work,
streamed like a tool call. Explicit `agent.compact()` bypasses the automatic
policy. The record of a compaction is a `CompactionPart` that arrives
`running`, receives replacement progress or summary updates, and settles
`complete` (the message swap applied, atomically) or `error` (a recorded,
non-fatal failure for automatic triggers). Turns can be started or ended by
compaction: the part embeds at the head of a send's turn (`beforeTurn`), at
its tail (`afterTurn`), or in its own engine-opened turn (`manual`).

---

## Breaking changes

### `Agent`

- `agent.history` is gone. The active conversation is `agent.messages`; there
  is no engine-held transcript. For turns, fold the event stream:

  ```ts
  const agent = new Agent(config);
  const transcript = new Transcript();
  agent.on((event) => transcript.apply(event));
  // render transcript.turns; persist transcript.state next to agent.snapshot()
  ```

- `agent.compact()` returns `Promise<boolean>` (applied vs. skipped) instead
  of `CompactionRecord | null`.
- A user message now commits when `turn:user` is emitted after setup, rather
  than when the provider request is made. Cancelling during `beforeTurn`
  compaction therefore leaves the user message in the active conversation and
  the transcript, and settles the agent turn as cancelled; emitted state is not
  unwound.

### Memory

- `AgentConfig.memory`, `AgentMemory`, `MemoryContext`, and `RecallResult` are
  removed. The Agent no longer performs automatic recall before a request or
  best-effort recording after a completed turn.
- The CLI's `ProceduralMemory` implementation and
  `@fifthrevision/axle-cli/memory` export are removed.
- For model-directed memory, provide ordinary retrieval and writing tools in
  `AgentConfig.tools`. Their storage, identity, scope, and authorization stay
  in the host application.
- For deterministic host-directed context, retrieve it before sending and
  attach it to an `Instruct`:

  ```ts
  const relevant = await memoryStore.search({ userId, query });
  const instruct = new Instruct({ prompt: query }).addContext(renderMemories(relevant), {
    title: "Relevant memory",
  });
  await agent.send(instruct).final;
  ```

  Persist complete transcripts by consuming `TurnEvent`s; transcript storage
  is separate from semantic memory.

### `AgentSession`

- Now `{ sessionId, messages }`. The `version`, `archive`, `compactions`,
  `turns`, and `sessionAnnotations` fields are removed, along with the
  constructor's session-version check — unknown keys in stored sessions are
  ignored, so old blobs restore without modification (their extra fields are
  simply dropped). To restore a transcript, seed a `Transcript` from
  your own persisted copy: `new Transcript(savedState)`.

### `Transcript`

- `TurnAccumulator` is renamed to `Transcript`.
- `TurnAccumulatorState` is renamed to `TranscriptState`.
- `TurnAccumulatorResult` is renamed to `TranscriptApplyResult`.
- `AccumulatableEvent` is renamed to `TranscriptInput`.
- `turns` is available directly for ordinary reads; `state` remains the
  complete serializable value.
- Session-level annotation targets are removed. Annotations belong to turns or
  parts; session-wide application state remains host-owned.
- `apply`, constructor seeding, and mixed host-event handling are otherwise
  unchanged.

### Deleted exports

- `History`, `HistoryInit` — the class dissolved into the Agent's private
  message state.
- `CompactionRecord` — replaced by `CompactionStamp` (see below).
- `AgentMemory`, `MemoryContext`, `RecallResult` — use ordinary tools or
  host-supplied `Instruct` context instead.

### `TurnEvent`

- `session:restore` deleted. It had no engine emitter; hosts seed their own
  accumulators via the constructor.
- `compaction:start` / `compaction:end` replaced by a part-level lifecycle
  mirroring actions: `part:start` delivers a `running` compaction part into
  its turn, `compaction:update` replaces transient `summary` and `progress`
  fields on it, and
  `compaction:complete` / `compaction:error` settle it. A compaction
  declined by `shouldCompactOnTrigger` emits nothing at all — there is no
  skip state and no removal rule.

### `CompactionPart`

- `record` removed. The part is self-contained and stateful:
  `{ id, type: "compaction", status: "running" | "complete" | "error",
summary?, progress?, error?, timing? }`. `summary` is the reader-facing text the
  compactor returned — a presentation choice, independent of the model-facing
  messages; `progress` is normalized from `0` to `1`, and completion sets it
  to `1`. If the callback returns no summary, the latest emitted summary
  remains; without one, the completed part renders as a bare divider. An
  `error` part records a failed attempt — non-fatal for automatic triggers:
  the send continued on the uncompacted conversation.

### `CompactionConfig` / callbacks

- `CompactionConfig` gains optional
  `shouldCompactOnTrigger(state, ctx) => boolean` — the synchronous policy for
  `beforeTurn` and `afterTurn`. Absent means every configured automatic
  trigger runs. A `false` emits nothing and runs nothing. Explicit
  `agent.compact()` bypasses this policy and invokes `compact` directly.
- `CompactionCallback` no longer declines: it returns
  `{ messages: AxleMessage[]; summary?: string }` (never `null` — move that
  automatic logic into `shouldCompactOnTrigger`) and throws on failure.
  `messages` is the complete new conversation; `summary` is the optional
  reader-facing text that settles the part — it need not mirror the messages
  ("Reduced the context by 50%" is valid). Its context loses `lastCompaction`
  and gains `id` (the engine-generated compaction id, shared with the part)
  and `emit({ summary?, progress? })` for replacing transient reader-facing
  state on the running part.
- `agent.compact()` returns `Promise<boolean>`: `true` after the configured
  compactor applies, `false` when no compactor is configured. Failures reject.
  Automatic-trigger failures no longer reject the send — the errored part is
  the record.
- To have prior output recognized on later runs (no
  summary-quoting-summary), stamp returned messages via metadata:

  ```ts
  {
    role: "user",
    content: summaryText,
    metadata: { axleCompaction: { id: ctx.id, role: "summary" } },
  }
  ```

  See `CompactionStamp` / `getCompactionStamp`. The stamp is a
  compactor-side convention — the engine does not read it; the part's
  summary comes from the callback's returned `summary`, and stamping stays
  optional.

### `PromptCompactor`

- Ships a bound `shouldCompactOnTrigger` alongside `compact` — wire both:
  `setCompaction({ shouldCompactOnTrigger: c.shouldCompactOnTrigger, compact: c.compact, triggers })`.
  The automatic threshold/empty logic lives in
  `shouldCompactOnTrigger`; explicit `agent.compact()` always runs.
- **0.29 upgrade warning:** `setCompaction({ compact: c.compact, triggers })`
  previously included `PromptCompactor`'s threshold policy inside `compact`.
  In 0.30 that configuration accepts every automatic trigger. Add
  `shouldCompactOnTrigger: c.shouldCompactOnTrigger` or an equivalent custom
  policy, or the conversation will compact at every configured boundary.
- Reports estimated progress through `ctx.emit` without exposing the generated
  token stream, and returns the summary text as the part's reader-facing final
  `summary`.
- Now returns **two** stamped messages — the summary and the recent-user-
  messages appendix — instead of one combined message. Conversations
  compacted by 0.29 restore fine; the carried-over unstamped summary may be
  quoted into the appendix once, on the first post-upgrade compaction.

## Unchanged

- `validateCompactedMessages`, both automatic triggers, threshold/target
  semantics, and the manual `compact()` queueing/cancellation behavior.
- All wire-layer message types; `Transcript`'s fold API (`apply`,
  `state`, constructor seeding).
