# Migrating to Axle 0.32.0

0.32.0 is the thinking-part release. It adds a portable thinking-disclosure
control, `display`, to the `reasoning` request option, renames the turn's
thinking fields, and collapses `generate()` onto the streaming transport.

The Axle CLI is a separate product; its changes are recorded in
[packages/axle-cli/CHANGELOG.md](../packages/axle-cli/CHANGELOG.md).

---

## Breaking changes

### Turn thinking parts: `text` is `raw`, `redacted` is gone

`ThinkingPart` on a transcript turn now carries what the provider handed
back, named for what it is:

```ts
// 0.31
interface ThinkingPart {
  text?: string;
  summary?: string;
  redacted?: boolean;
  continuity?: ThinkingContinuity;
  providerMetadata?: Record<string, unknown>;
}

// 0.32
interface ThinkingPart {
  summary?: string; // the provider's condensed account
  raw?: string; // the chain of thought itself; open-weight models only
  continuity?: ThinkingContinuity;
  providerMetadata?: Record<string, unknown>;
}
```

Render `summary ?? raw`. Neither present is the withheld state, whatever
the cause, and it renders the same. There is no flag to consult. A part
opens with no content field; a field appears only once a delta wrote it,
so never test for `""`.

Anthropic, OpenAI, and Gemini populate `summary`. `raw` arrives from
open-weight models through OpenAI's `gpt-oss` and chat-completions
endpoints. Anthropic's block content was previously written to `text`; it
is a summary and now lands in `summary`.

The message-layer `ContentPartThinking` on `AxleMessage` is unchanged: it
keeps `text`, `summary`, and `redacted` because it exists to be echoed back
to the provider, not read. `redacted` there now means only that the
provider substituted an opaque payload (Anthropic `redacted_thinking`,
OpenRouter `reasoning.encrypted`); a hidden block is no longer marked
redacted, and echoes as an ordinary `thinking` block with its signature.

Persisted turns from 0.31 carry the old shape. Axle ships no shim; a host
that stores turns decides whether to migrate rows or render both shapes.

### Thinking events renamed and reshaped

| 0.31                                          | 0.32                                               |
| --------------------------------------------- | -------------------------------------------------- |
| `thinking:delta` (stream and turn)            | `thinking:raw-delta`                               |
| `thinking:summary-delta`                      | unchanged                                          |
| stream `thinking:start` `.redacted`           | removed                                            |
| stream and turn `thinking:update` `.redacted` | removed                                            |
| stream `thinking:end` `{ final: string }`     | `{ summary?, raw? }`, each present only if written |

The event names now say which field they grow. `thinking:end` reports both
buffers because a part can receive both kinds of delta and the previous
single string reported whichever arrived last.

### `generateStep` is removed

The single non-streaming model request, exported since 0.29.0 as
`generateStep`, no longer exists: there is no non-streaming request to make.
Callers who used it for one model step without the tool loop should call
`stream()` with `maxSteps: 1` and read `final`, or `generate()` with the same
option.

## Behavior changes

### `generate()` runs on the streaming transport

`generate(o)` is now exactly `stream(o).final`. Its signature, overloads, and
result type are unchanged, and the request it sends is the streaming request.
Three things move as a result:

- **Anthropic's implicit `max_tokens`** on `generate()` rises from 21,000 to
  the model's registry ceiling, else 64,000, the same as `stream()`. The
  buffered constant existed only to stay under the Anthropic SDK's
  non-streaming timeout guard, which streaming requests never hit.
- **Retryable failures surface at first byte.** The SDKs retry 429s, 5xxs,
  and connection errors before the response starts, for streaming and
  buffered requests alike, so nothing is lost there. A connection that drops
  mid-response is an error carrying the completed steps, as it always was on
  `stream()`; a buffered request had a shorter window for the same failure.
- **`raw` on the error result** carries the streaming adapter's assembled
  data rather than the vendor's buffered response object.

`AIProvider.createGenerationRequest` is gone from the provider interface.
Custom providers implement `createStreamingRequest` only.

### Enabling reasoning now requests disclosed thinking

Every `reasoning: "on"` or `reasoning: { effort }` request now asks the
provider to show its thinking wherever a request field exists:

| Provider         | 0.31 sent               | 0.32 sends                                  |
| ---------------- | ----------------------- | ------------------------------------------- |
| Anthropic        | `thinking: { type }`    | `thinking: { type, display: "summarized" }` |
| OpenAI Responses | `reasoning: { effort }` | `reasoning: { effort, summary: "auto" }`    |
| Gemini           | `includeThoughts: true` | unchanged                                   |

On Anthropic, every current Claude model defaults `display` to `omitted`, so
0.31 callers received thinking parts with empty text and no
`thinking:delta` events. On OpenAI, 0.31 never requested summaries, so no
summary parts arrived. Both now stream thinking text. Anthropic streams
thinking tokens before the first text token under `summarized`, so time to
first text token rises on those requests.

`"default"` and `"off"` are unchanged and send nothing for display.

To keep the 0.31 wire behavior, opt out per request:

```ts
// 0.31: thinking enabled, nothing disclosed on Anthropic or OpenAI
await generate({ provider, model, messages, reasoning: { effort: "high" } });

// 0.32: the same wire shape
await generate({
  provider,
  model,
  messages,
  reasoning: { effort: "high", display: "hidden" },
});
```

`display: "hidden"` sends `omitted` on Anthropic, `includeThoughts: false`
on Gemini, no summary field on OpenAI, and `reasoning: { exclude: true }` on
OpenRouter. Generic Chat Completions endpoints and Together have no field.
On every route the turn receives no thinking content under `"hidden"`: the
step reader withholds it, and the message keeps whatever the wire carried.
This matters on OpenRouter, where `exclude` leaves `reasoning_details` text
in place, so `generate()` callers reading `result.final.content` there still
see the summary on the message part.

## Additions

- `ReasoningSetting` object form gains `display?: "visible" | "hidden"`
  (default `"visible"`). `ReasoningDisplay` is exported.
- `display` controls whether thinking is disclosed, not its form. Anthropic,
  OpenAI, and Gemini return a summary; open-weight models return raw text.
  The part records which arrived.
- Fine-grained values stay in `providerOptions`: OpenAI `concise` and
  `detailed` summaries, Anthropic's `updates` display. Overriding `thinking`
  on Anthropic replaces the whole object, `type` included.
- `ThinkingContinuity` gains an `openrouter` member carrying the
  `reasoning_details` entry's `type`, `id`, `format`, `index`, `signature`,
  and `data`.
- Chat completions now read `reasoning_details` on both the streaming and
  non-streaming paths, key thinking parts on the entry `index`, and file
  `reasoning.text` under `summary` when its `format` names an upstream that
  never discloses raw thinking (`anthropic-claude-v1`), else under `raw`.
  Claude summaries through OpenRouter previously landed in `raw`.
- The chat-completions request builder echoes `reasoning_details` on
  assistant messages for the `openrouter` vendor, so multi-turn Claude
  through OpenRouter keeps its signatures. Generic endpoints and Together
  are unchanged.
- Gemini signature-only parts (empty text with a `thoughtSignature`) are no
  longer dropped: they attach to the open thinking part or become a
  continuity-only thinking part. The Gemini request builder echoes thinking
  parts that carry a signature as thought parts, in source order; text and
  function-call parts are now sent in source order too, where they were
  previously grouped by type.
