# Migrating to Axle 0.36.3

The Axle CLI is a separate product; its changes are recorded in
[packages/axle-cli/CHANGELOG.md](../packages/axle-cli/CHANGELOG.md).

---

## Behavior changes

### A cancelled model call keeps only what was written

When a turn was cancelled, or ran out of `turnTimeoutMs`, while the model
was still writing its response, the conversation kept every part the
response had opened. A tool call that had started streaming stayed in the
assistant message with no result, and a text part opened and not yet
written to stayed as an empty string. The next request sent them, and
providers rejected it: after one such turn, every later send on that agent
failed.

The partial assistant message now holds only the parts in which something
was written:

| The part when the cancel landed                                | In the partial |
| -------------------------------------------------------------- | -------------- |
| A tool call, its arguments finished or not                     | Dropped        |
| Text with nothing written yet                                  | Dropped        |
| Thinking with no text, summary, redacted content or continuity | Dropped        |
| Text or thinking with content, and every other part            | Kept as before |

When nothing is left, there is no partial: `error.partial` is `undefined`
and no assistant message is added.

```ts
// Cancelled while the model was writing a tool call, nothing before it.
// Before
agent.messages.map((m) => m.role); // ["user", "assistant"]
error.partial?.content.map((p) => p.type); // ["tool-call"]

// 0.36.3
agent.messages.map((m) => m.role); // ["user"]
error.partial; // undefined
```

This applies to `partial` and `messages` on `AxleAbortError` and
`AxleAgentAbortError`, from `stream()`, `generate()` and `agent.send()`, and
to `agent.messages`. The send rejects as before, with the same error. A step
that completed is unaffected: its tool calls are answered as 0.36.2
describes.

Code that read `error.partial` to see which tool the model was about to
call no longer finds it there. The `tool:request` and `tool:args-delta`
stream events still fire, and the turn still holds the action part, settled
`cancelled`.

A session saved by an earlier version that already ends in an unanswered
tool call or an empty text part is not repaired. Remove the trailing
assistant message before sending on it again.

The reasons are in
[architecture/tool-loop.md](./architecture/tool-loop.md), invariant 11.

### Anthropic thinking has `continuity` only once it has a signature

An Anthropic thinking part used to start with
`continuity: { provider: "anthropic", signature: "" }`, on the
`thinking:start` stream event, on the turn's part at `part:start`, and on
the message part until the signature arrived. `continuity` is now set only
once the signature, or a redacted block's data, has arrived: it first
appears with the `thinking:update` that carries it, and a thinking part
whose signature never arrived has no `continuity` field.

Code that tested `part.continuity` to find a signed Anthropic thinking part
is now right without also checking the signature. Requests are unchanged:
unsigned thinking was never sent back.

The reasons are in
[architecture/thinking.md](./architecture/thinking.md), invariant 8.
