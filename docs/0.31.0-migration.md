# Migrating to Axle 0.31.0

0.31.0 reworks `PromptCompactor`'s sizing contract: size targets move to the
units they can actually be enforced in, and the provider output cap stops
doubling as the size bound.

The Axle CLI is a separate product; its 0.31.0 changes (invocation grammar,
job schema, configuration homes) are recorded in
[packages/axle-cli/CHANGELOG.md](../packages/axle-cli/CHANGELOG.md).

---

## Breaking changes

### `PromptCompactor`

`targetTokens` and `recentUserMessages` are removed; `summaryWords` and
`appendixTokens` replace them:

```ts
// 0.30
new PromptCompactor({
  provider,
  model,
  prompt,
  thresholdTokens: 100_000,
  targetTokens: 30_000,
  recentUserMessages: 10,
});

// 0.31
new PromptCompactor({
  provider,
  model,
  prompt,
  thresholdTokens: 100_000,
  summaryWords: 1_500, // default 1000
  appendixTokens: 15_000, // default: thresholdTokens / 10; 0 disables
});
```

- **`summaryWords`** is a soft bound enforced by escalation: the prompt
  steers the size in words, the result is measured in words, one
  relative-shrink rewrite runs if it lands over ~1.3× the request, and
  word-boundary truncation is the last resort. Anyone depending on the old
  hard "result ≤ targetTokens" guarantee should measure the returned
  messages.
- **`appendixTokens`** budgets the recent-user-message appendix directly
  (up to the last 10 user messages, evicted oldest-first). The message
  _count_ is no longer configurable — a count is a size proxy that fails
  exactly when size matters (one pasted log blows any count).
- **`maxOutputTokens` is no longer sent.** The summarizer request carries
  no output cap; the provider's own ceiling applies. Previously, thinking
  tokens (which share the output cap on every provider) could consume the
  entire budget and fail the compaction with `COMPACTION_EMPTY_SUMMARY`;
  thinking models now summarize reliably at any reasoning setting.
- **Unset `reasoning` stays unset.** 0.30 coerced it to `false`, which
  OpenAI-compatible wires sent as `reasoning_effort: "none"` — a request
  always-thinking models reject. Pass `reasoning: false` explicitly if you
  relied on forcing thinking off.

### `reasoning` is a portable setting, not a boolean

`reasoning?: boolean` on `Agent`, `generate()`, `stream()`, and
`PromptCompactor` becomes `reasoning?: ReasoningSetting`:

```ts
type ReasoningEffort = "low" | "medium" | "high";
type ReasoningSetting = "default" | "off" | "on" | { effort: ReasoningEffort };
```

Booleans are a type error. The nearest replacements and what changes on the
wire:

| 0.30    | 0.31                   | Behavior change                                                                                                                                                                                                       |
| ------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| omitted | omitted or `"default"` | none; no reasoning fields are sent                                                                                                                                                                                    |
| `true`  | `"on"`                 | **medium effort, not high.** 0.30 sent `effort: high` (OpenAI, Chat Completions, Anthropic adaptive) and `thinkingLevel: high` (Gemini 3). Pass `{ effort: "high" }` to keep the old depth.                           |
| `false` | `"off"`                | **Anthropic now sends `thinking: { type: "disabled" }`** instead of nothing; Fable and Opus 5 at xhigh/max reject it. **Gemini now sends `thinkingBudget: 0`** instead of `minimal`/`low`/`128`; Gemini 3 rejects it. |

Other wire changes under the same option:

- **Gemini aliases and unknown IDs get thinking controls.** 0.30 silently sent
  nothing for `gemini-flash-lite-latest`, `gemini-flash-latest`, and any
  non-2.5/3.x ID. They now take the `thinkingLevel` route; only
  `gemini-2.5-*` uses `thinkingBudget`.
- **Anthropic route selection is a fixed list, not a regex.**
  `claude-opus-5`, `claude-sonnet-5`, and `claude-fable-*` were misrouted to
  a manual budget that those models reject; they now take adaptive thinking.
  Legacy budgets (2,048 / 8,192 / 16,384 for low / medium / high) apply only
  to Haiku 4.5, Opus 4.5, and Sonnet 4.5. Retired models (Opus 4 / 4.1,
  Sonnet 4, Sonnet 3.7) are not routed.
- **Together sends `reasoning_effort` alongside `reasoning.enabled`** when
  reasoning is on.
- **Anthropic `stream()` requests default `max_tokens` to the model's registry
  ceiling**, else 64,000. 0.30 intended this but the registry lookup missed,
  so a heuristic ran; the numbers match for current models, but Claude 3.x
  IDs that previously got 8,192 now get 64,000 and are rejected unless you
  pass `maxOutputTokens`. `generate()` moves from 16,000 to 21,000, the
  largest cap the SDK sends without streaming, so every legacy preset fits.
