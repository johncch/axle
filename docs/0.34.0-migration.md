# Migrating to Axle 0.34.0

0.34.0 has no breaking API changes so far. `chatCompletions()` gains a
default request timeout and reports a timeout as one.

The Axle CLI is a separate product; its changes are recorded in
[packages/axle-cli/CHANGELOG.md](../packages/axle-cli/CHANGELOG.md).

---

## Behavior changes

### `chatCompletions()` requests time out after ten minutes

A `chatCompletions()` request with no `timeoutMs` used to wait indefinitely
for the endpoint to start responding. Each attempt now gives up after ten
minutes, the default the OpenAI and Anthropic SDKs already apply. The timer
covers the wait for the response to start, not the stream that follows, and
it restarts on every retry, so with the default `maxRetries: 2` an endpoint
that never answers fails after about thirty minutes.

Pass `timeoutMs` to choose a different limit:

```ts
const provider = chatCompletions("http://localhost:11434/v1", {
  timeoutMs: 30 * 60_000,
});
```

`anthropic()`, `openai()`, and `gemini()` are unchanged: without `timeoutMs`
they use whatever their SDK does.

### A `chatCompletions()` timeout fails as `TimeoutError`

When an attempt timed out and no retries were left, the failure carried
`type: "AbortError"` and the message `Request aborted`, the same as a
cancellation. It now carries the timer's own error:

| Field     | 0.33                | 0.34                              |
| --------- | ------------------- | --------------------------------- |
| `type`    | `"AbortError"`      | `"TimeoutError"`                  |
| `message` | `"Request aborted"` | `"Request timed out after <n>ms"` |

Code that matched `AbortError` to detect a `chatCompletions()` timeout
should match `TimeoutError`. Aborting through the caller's own signal is
unchanged.
